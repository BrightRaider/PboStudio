# Etappe E0 — Beweis: Ergebnis

Datum: 2026-11-05. **Gate G0: bestanden.** Der Plan bleibt bei Rust ([ADR-0001](../adr/0001-neubau-in-rust.md)).

## Was gebaut ist

Der Arbeitsbereich `rust/` mit vier Crates in der Schichtung aus [ADR-0003](../adr/0003-workspace-und-abhaengigkeiten.md):

| Crate | Inhalt |
|---|---|
| `pbo-core` | reine Logik, **keine Abhängigkeit** (`cargo tree` zeigt nur das Crate selbst): Spannungsumrechnung (SVI2 und SVI3), Auslesen des P-State-Registers, Curve-Optimizer-Maske und -Wert, Prozessor-Erkennung aus CPUID, PM-Tabellen-Layouts mit Plausibilitätsprüfung, Sicherungen der Chiplets und Kerne. 17 Tests. |
| `pbo-os` | Thread-Anheftung mit Wächter, CPUID, APIC-Ids, Kindprozess im Job-Objekt (beendet sich auch bei einem Abbruch). |
| `pbo-smu` | Der PawnIO-Treiber (Protokoll, zwei Module), SMN- und MSR-Lesen, SMU-Befehle, PM-Tabelle, die PCI-Bus-Sperre, die HWiNFO und andere teilen. |
| `pbo` | Das Programm: `pbo diag`, nur lesend, schreibt `pbo-diag.txt`. |

## Gate-Kriterien

Verglichen wurde mit der C#-Fassung (`PboProbe`), im selben Zeitraum auf derselben Maschine, einem Ryzen 7 5800X3D.

| Kriterium | Rust | C# | Ergebnis |
|---|---|---|---|
| Curve Optimizer je Kern | −20 −25 −30 −30 −28 −30 −30 −30 | −20 −25 −30 −30 −28 −30 −30 −30, auch die Masken 0x0 bis 0x700000 | **identisch** |
| SMU-Version | 0x00384E00 | 00384E00 | identisch |
| Topologie | 1 Chiplet, 8 Kerne, 16 Threads, Slots 0.0 bis 0.7 | 1 CCD / 1 CCX / 8 cores / 16 threads | identisch |
| PM-Tabelle | Version 0x00380905, 0x5D0 Byte, DRAM 0xDAD50000, 372 Werte | Version 0x00380905, 1488 Byte, DRAM 0xDAD50000, 372 Werte | identisch |
| Grenzen aus der Tabelle | PPT 142 W, TDC 95 A, EDC 130 A, Temperatur 90 °C | Indizes 0, 2, 8, 4: 142, 95, 130, 90 | identisch |
| Live-Werte | 53,1 °C, 42,9 W, 15,3 A, 104,9 A | andere Zeitpunkte | gleiche Größenordnung, **nicht gleichzeitig** gemessen |
| APIC-Ids | 16 Ids, 0 bis 15 | das Protokoll des C#-Programms nennt 16 gelesene Ids | Anzahl gleich; **Id für Id nicht verglichen**, die C#-Ausgabe zeigt sie nicht |
| Dateigröße | **275 KB** | 45 MB (selbstentpackend) | Ziel war unter 3 MB |
| Job-Objekt mit Affinität | 1,00 Kerne bei zwei Threads | | die Begrenzung hält |

## Dazu gekommen

- **Kernspannung** auf einem Zen 3: die SVI2-Telemetrie (1,219 / 1,219 / 1,156 V) und die VID je Kern (alle Kerne gleich, eine gemeinsame Schiene) stimmen überein. Im C#-Lauf steht außerdem im PM-Tabellen-Index 11 der Wert 1,219 V, derselbe Wert wie in der Telemetrie zu dieser Zeit. Das ist ein Kandidat für die Spannung aus der Tabelle, nicht geprüft.
- **Eine Neuerung gegenüber der C#-Fassung:** Das Curve-Optimizer-Lesen geht in Rust über den fertigen Mailbox-Befehl des Moduls (`ioctl_send_smu_command`), die C#-Fassung schreibt die Mailbox-Register selbst. Beides liefert dieselben Werte.
- **Die PCI-Bus-Sperre** (`Global\Access_PCI`) wird um jeden SMN- und SMU-Zugriff genommen, wie bei den üblichen Überwachungsprogrammen.

## Was nicht gezeigt ist

- **Nichts auf Zen 4 oder Zen 5.** Diese Familien sind in `pbo diag` gekennzeichnet („nicht an Hardware geprüft"), die Adressen kommen aus der Bibliothek. Für die Kernspannung gibt es dort bewusst „n/a" statt einer Zahl.
- **Kein Schreiben.** E0 liest nur. Das Schreiben mit Rücklesen kommt in E3.
- **Keine Last,** keine Testprogramme, kein Absturzverhalten. Das ist E3.
- Die Dateien sind **nicht signiert** (Entscheidung des Eigentümers, [ADR-0010](../adr/0010-verteilung.md)).

## Belege

Die Berichte liegen unter [`evidence/`](../evidence/): die Ausgabe von `pbo diag` und die beiden Ausgaben der C#-Fassung (`e0-5800x3d-csharp-probe.txt` und `e0-5800x3d-csharp-pmtable.txt`).

## Nachvollziehen

```
cd rust
cargo test --workspace
cargo build --release
```

Dann `rust\target\release\pbo.exe diag` als Administrator starten (`--raw` hängt die ganze PM-Tabelle an). Das Programm schreibt `pbo-diag.txt` neben die `pbo.exe`.

## Als Nächstes

- **E1, Spezifikation:** Die 453 Tests werden zu Vektoren (`parity` und `new`).
- **`pbo diag` für Tester auf Zen 4 und 5:** Es ist das Werkzeug, mit dem sich die offenen Punkte (Spannung, Tabellenpositionen, Curve-Optimizer-Befehl) an echter Hardware klären lassen. Dafür braucht es eine veröffentlichte Fassung, die ein Tester starten kann.
